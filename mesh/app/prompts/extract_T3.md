# T3 硅谷 BD 团队 行程与建联 抽取规则（数据形态层；团队价值判断见 team_svbd）
数据形态四种，同一份上传里可能混合：
A 行程日历（ICS / 日程表 CSV）：一行一个日程。大会合并成一段；注册/取证/签到/订机酒等运营性条目过滤（整份只输出一条 zone=2 说明"运营性条目按规则不列"）。"日历订阅 ≠ 实际参加"：只有日历里的活动写 cert=日历订阅；有会议记录/建联记录佐证的才写"已参加/已会面"。
B 见的人的记录（会议记录 / 会后备忘）：一段一个人或一场会。抽：对方实名 + 公司 + 层级 + 谈了什么（事实）+ 对方的判断（kind=judgment，标"受访者陈述"）+ 状态（初次接触/在聊/已约下一步）。对方对第三方的评价、对我们报价的态度、我们的谈判立场 → zone=5。
C 创业者数据库增量（human / company / interaction / take 四类表）：只抽**本期区间内新增或有更新的行**（看创建/更新时间列；没有时间列则整份视为本期）。
 - human：姓名 + 公司 + 职位 + 所在城市 + 怎么认识的（渠道）→ zone=3 或 4，L1，roles 写"潜在成员/嘉宾/资源"中合适的。
 - company：公司名 + 赛道 + 阶段 + 创始人 + 一句话产品 → zone=4，L1。融资金额/估值不写，只写轮次。
 - interaction：谁和谁、何种形式（会面/邮件/活动同场）、谈了什么 → zone=3。
 - take：团队对某人/某公司/某赛道的判断 → kind=judgment，zone=4，L1；带情绪或对人的评价 → zone=5。
D LinkedIn / X 动向（若有）：只抽对方公开发布的、与其公司业务相关的动态；私信内容 → zone=5。
- 每条都要想一想"国内哪个团队用得上"，写进 roles/entities 便于关系匹配（规则见 team_svbd）。
- source_label 只用：硅谷 BD 团队日历（ICS）/ 硅谷 BD 团队日程表 / 硅谷 BD 团队会议记录 / 硅谷 BD 团队建联记录 / 硅谷 BD 团队创业者数据库。
- 时间戳、数据库行号放 pointer。
