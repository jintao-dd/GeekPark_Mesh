# 硅谷 BD 团队 · 团队专属规则（叠加在数据类型规则之上；管理员可整份替换）

## 这个团队的价值在哪
硅谷 BD 团队是极客公园在硅谷的眼睛和手。它的数据是全公司最稀缺的：谁在硅谷做什么、谁刚起步、谁准备回国或进中国、哪些判断只有当面聊才听得到。抽取的目标不是记流水账，而是把每一次接触都变成国内团队能接上的线头。宁多勿漏；⑤区照旧硬拦。

## 四类对象，每类要挖到什么
1. 人（human）：实名 + 公司 + 层级 + 所在地。额外挖：和国内的关系（华人创始人 / 曾在中国公司任职 / 产品面向中国市场 / 计划来华）、是否愿意接受采访或上节目、是否可能成为前沿社或社群成员、是否是潜在客户或潜在 LP 相关方。
2. 公司（company）：赛道 + 阶段（只写轮次，不写金额）+ 创始人 + 一句话产品 + 是否已进中国 / 有中国竞品。额外挖：与国内哪家公司是同一赛道、上下游、或明显的对标。
3. 接触（interaction）：形式 + 谈了什么 + 状态。额外挖：对方提出的诉求（想找中国合作伙伴 / 想被报道 / 想参加活动 / 想融资——最后一项只写"在融资"不写数字）。
4. 判断（take）：团队对人、公司、赛道的判断，全部标 kind=judgment。挖赛道级判断（"这类产品在硅谷已经卷起来了"）比挖单公司判断更有价值；对具体人的正负评价 → zone=5。

## 路由：每条必答"国内谁用得上"
写进 roles（可多选），并在 entities 里带上能匹配的国内主体名：
- 编辑部：值得采访 / 值得写 / 是国内某选题的海外参照 → roles 加"嘉宾"或"资源"，entities 加相关话题词。
- 投资团队：早期项目、赛道信号 → roles 加"资源"，signals 加"融资"（仅限轮次信息）。
- 商业化团队：对方是大厂或有预算的公司、有来华营销需求 → roles 加"意向客户"。
- Global Partnership 团队：对方有来华交流意愿、适合前沿社活动 → roles 加"潜在成员"或"嘉宾"。
- 音频播客团队 / 视频号团队：对方能讲、有话题性 → roles 加"嘉宾"。
- 英文站：适合英文报道 → roles 加"资源"。
判断不出用得上谁，写"无"，不硬凑。

## 本期区间
日历与数据库都按"本期区间"过滤；区间外的只在能说明状态变化时带一句（"上期初次接触，本期已约下一步"）。

## 不抽
运营性日程、内部链接、私信原文、对人的评价、我们的谈判立场与报价反应、任何金额。
