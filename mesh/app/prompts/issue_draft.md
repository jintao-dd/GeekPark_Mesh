# 生成一期周报草稿（主视图 + 本期未汇入 + Data Source）
你会拿到：有效内部条目、外部媒体条目、归档比对得出的"首次进入记录"候选、上一期摘要。

## 主视图五节 + 两个附录
1 可同步的关系（权重最高）：**判定只看 owner_team 是否不同，不看来源记录条数**——同一团队多通道重叠已在 cross-channel-merge 阶段合并，绝不能因为一条事有三行来源就当成跨部门关系。同一主体在 ≥2 个**归属团队**出现，或一方接触另一方明显用得上，或外部有内部无。每张卡：label（从标签库选）、weak（true=同赛道/同公司/单向/外部→内部；false=两边都有具体记录）、title、body（一句话）、details（各团队各自的事实要点，≥2 条；弱卡可为空）、sources（逐条，按来源写法）、teams（相关团队；用 "→ 团队" 表示可能用得上方）。待核对与尚未接触两类置顶。冲突只并列 + "两处记录待核对"，不替谁选一个。
标签库：两处记录待核对 · 一方有需求，另一方尚未接触 · 一方接触了，另一方正在接触 · 已公开报道，内部也在用 · 同一件事，两个部门各知一半 · 采访对象也是客户 · 两个部门各有判断 · 已联动 · 一方接触，另一方用得上 · 外部在热聊，我们还没碰 · 海外接触，国内可能承接 · 海外新发现，国内尚未接触 · 中英文站同周各自成稿 · 一方报道了，另一方在接触 · 同一赛道，各自在做 · 同一公司，不同触点 · 已排期，内容侧待安排。不得自创标签。
2 接触过的人和公司：按组成卡（编辑部一手对话 / 商业化团队在跟进的客户 / Global Partnership 团队 · 合作伙伴与机构 / Global Partnership 团队 · 前沿社活动嘉宾 / 硅谷 BD 团队 · 见过的人 / 硅谷 BD 团队 · 新进数据库的创业者与公司 / 音频播客嘉宾 / 其他），组内按子分类排胶囊；每个胶囊 rows：身份 / 时间 / 要点 / 备注（可选）/ 来源。实名。
3 关注了什么：四组关键词墙（关注的领域 / 公司与人 / 关注的技术 / 关注的类型）；每个胶囊 rows 按团队分行写关注形式（文章标题+链接、对话、选题、会议提及、英文站、视频号本周表现、播客某期）；teams 列出相关团队；weight = 形式数 + 团队数。
4 日程与计划：分组（在写的选题 / 将参加、将发生的活动 / 将发布、将启动 / 海外社媒）；每项 cert 取 已排期|在做|已完成|计划中|在谈|初步想法|日历订阅|外部事件（拿不准一律"初步想法"）；rows 给状态与来源。
5 沟通中提到的看法：按主题合并（如 具身与硬件 / AI 助听器 / Agent 与模型 / 众筹与出海 / 办公 AI 工具），每条 text 只写判断内容，不写发言人，来源到团队级。
0 本期未汇入：本期尚未汇入的来源与按规则未列的条目（以数据可用性口吻，不点名团队"没做"）。
Data Source：按 **owner_team（归属团队）** 平级列本期各自贡献了什么，**不按采集通道列**——聚合器抓来的内容要落到它真正归属的团队（如硅谷 BD 团队的日历经聚合器进来，仍计入硅谷 BD 团队）。「内容中心·数据聚合」不作为一个团队出现。未接入的 off=true。

## 首屏
question 固定："这两周，极客公园接触了谁、关注了什么、和谁产生了关系"。
lead 三句：① 不写日期（日期另有字段）② "本期首次进入记录的公司与人：…；首次出现的话题：…"（从候选里挑 5–8 个信息量最大的）③ "本期由 X、Y、Z 团队的记录汇成"（按 owner_team 列，只列已汇入的，不写谁没交）。约 100 字，无排序、无评价、不重复数字。
kpis：可同步的关系 N / 接触过的人 N+ / 创始人级一手对话 N / 关注的事 N。

## 交叉分析（每期必做，不是可选项）
把每个团队的条目当成一张网的一个角，逐一对照其余团队：同一个人、同一家公司、同一个话题、同一个城市/活动、同一条产业链上下游。海外两团队与国内团队的对照优先做完：硅谷 BD 见的人 × 编辑部选题 / 投资在看 / 商业化客户；GP 的前沿社会员与合作伙伴 × 编辑部对话 / 播客嘉宾 / 活动档案；视频号本周表现好的话题 × 编辑部在写的选题 / 播客在录的话题。对上的进第 1 节；单边但明显有承接可能的用 "一方接触，另一方用得上" 或 "海外接触，国内可能承接"。没有对上的不硬凑。

## 硬性约束
- ⑤区、L3 内容一个字都不能出现（输入里已拦，但你也要再查一遍）。
- 全篇不得出现禁用词。判断类文字必须能被识别为判断。
- 每张卡、每个胶窗都要有来源。
