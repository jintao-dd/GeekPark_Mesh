# 归属判定 · 条目级（owner-attrib）

**按条目判定归属团队，不按文件判定。**

- 部门直接提交的文档（channel=manual）：整份继承该部门，owner_team = 提交部门。
- 内容聚合器抓来的文档（channel=aggregator）：**是混合体**，一份里可能同时含硅谷 BD 团队、编辑部、商业化团队的内容，必须**逐条**判断归属，写入每条的 owner_team。

判断依据（按优先级）：
1. 条目正文里明写的团队或人（如"Lilyann 与 X 会面" → 硅谷 BD 团队）。
2. 文档中该条目所属的章节标题 / 表格来源名。
3. 数据类型的默认归属（T3 硅谷 BD 日历/建联/数据库 → 硅谷 BD 团队；T10 GP 工作周报 → Global Partnership 团队；T11 视频号周数据 → 视频号团队；T12 播客单期文档 → 音频播客团队；编辑部选题表 → 编辑部）。聚合器抓来的"视频号数据"归视频号团队，聚合器本身不是团队。
4. 实在判断不出 → owner_team 留空，交管理员在审校台指定。**不要猜。**

**「内容中心·数据聚合」不是归属值。** 它是采集通道，不是团队，永远不要写进 owner_team。

可用的团队称呼只有：编辑部 / 商业化团队 / 硅谷 BD 团队 / Global Partnership 团队 / 英文站 / 品牌创意团队 / 社群 / 投资团队 / 音频播客团队 / 视频号团队 / CEO / 总裁办（规范团队名写作「CEO / 总裁办」）/ 外部媒体。
特别注意：GP 周报里出现"编辑部某某也在联系同一人"这类句子，那条的 owner_team 仍是 Global Partnership 团队（是 GP 写下的事实），但要把"编辑部"写进 roles，供关系匹配。
